> 只报告事实，不含选型建议。检索时间：2026-09-05，以各家官方 API 文档为准，社区信息单独标注。

## 2. 逐模型要点

### 2.1 doubao-seed-2.0-lite（新增候选，火山方舟）

- **全模态**：豆包 Seed 2.0 系列为全模态理解模型，原生统一理解视频/图像/音频/文本；lite 档为「性能与成本均衡」，另有 mini 档面向「低延迟高并发」、pro 档面向高复杂度推理。【官方博客 + 媒体】
- **思考模式**：方舟对 Doubao 系列提供统一 `thinking` 参数（`enabled`/`disabled`/`auto`，`auto`=模型自行判断）；官方对比页明确 `disabled` =「关闭思考模式，模型直接回答问题，不会进行思考」。第三方平台（LinkAI）对 seed-2.0 系列的描述为「支持思考模式和非思考模式的有效融合」——即 **lite 可在无思考模式下运行**。用户「确定可识图且无思考」的认知与该口径一致；**lite 的出厂默认档位（hybrid 下默认思考与否）未从官方文档文字中核实到**，接入前建议以模型列表页/实测为准。
- **价格**（方舟定价页）：输入 0.6 元/百万 tokens（≤32k）、输出 3.6 元/百万 tokens；（32k,128k] 档输入 0.9。【官方定价页快照】
- 来源：[火山方舟模型参数列表](https://www.volcengine.com/docs/82379/2662855)、[方舟多模态深度思考文档（disabled 语义）](https://www.volcengine.com/docs/6492/2165108)、[方舟模型价格](https://www.volcengine.com/docs/82379/1099320)、[Seed2.0 官方博客](https://seed.bytedance.com/zh/blog/seed2-0-正式发布)、[LinkAI 模型页（社区）](https://link-ai.tech/models)、[InfoQ 报道](https://www.infoq.cn/article/Kcqq2ifEZCJaK8o0TxN1)。

### 2.2 GLM-5.3-Flash：思考强制开启，只能调档不能关

- 官方「深度思考」文档原文：**「GLM-5.3-FLASH 不再支持关闭思考（API 请求中 thinking.type 传 disabled 将会报错），请确保开启思考」**。
- GLM-5.3 系支持思考强度级别（`low`/`high`/`max`），**不再支持禁用**；第三方迁移指南（七牛云）建议：把 `disabled` 改为 `enabled`，并**按场景把强度设为 low，避免默认高档拖慢简单任务响应**（「避免默认 max 档位拖慢简单任务的响应速度」为该文建议）。
- 注意：`reasoning_effort` 参数名来自第三方解读，官方 thinking 文档页对强度参数的准确写法**需复核**。
- 来源：[智谱深度思考文档](https://docs.bigmodel.cn/cn/guide/capabilities/thinking)、[GLM-5.3-Flash 模型页](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[GLM-5.3 模型页](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)、[七牛云迁移解读（社区）](https://news.qiniu.com/archives/1787109869202)。

### 2.3 DeepSeek-V4-Flash：开/关 + 强度双轨，非思考模式一等公民

- V4-Pro 与 V4-Flash 均**同时支持非思考模式与思考模式**，1M 上下文；思考强度支持 `reasoning_effort`（`high`/`max` 两档在 V4 公告中列出）。
- 官方「思考模式」文档给出双 API 口径：
  - Chat Completions：`{"thinking": {"type": "enabled"/"disabled"}}`；
  - Responses API：`{"reasoning": {"effort": "none/low/high/max"}}`，**`none` 即关闭思考**。
- 默认行为：社区指引称普通请求默认 `enabled` + effort `high`，Agent 类请求自动 `max`（**社区信息**）。
- **思考模式下的参数限制（官方明确）**：`temperature`、`top_p`、`presence_penalty`、`frequency_penalty` 不生效（「设置不报错但也不生效」）。
- **V4-Flash-Vision-Exp 与思考参数的组合**：vision-exp 为 V4-Flash 基座加视觉的实验版，官方页未见其思考参数差异说明——按同基座推断行为一致，**需实测确认**。
- 来源：[DeepSeek 思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)、[V4 预览公告](https://api-docs.deepseek.com/zh-cn/news/news260424)、[DeepSeek 更新日志](https://api-docs.deepseek.com/zh-cn/updates)、[知乎指引（社区）](https://zhuanlan.zhihu.com/p/2033177091173262427)。

### 2.4 Qwen3.8-Flash：enable_thinking + thinking_budget，控制粒度最细

- 百炼官方：qwen3.8 系列可通过 **`enable_thinking`** 控制思考开关（视觉理解文档明确覆盖 qwen3.8 系列）；开启后可用 **`thinking_budget` 限制思考过程长度**。
- Responses API 走 `reasoning.effort`；提示词级软开关 `/no_think`、`/think` 官方文档亦列明（`enable_thinking=true` 时 `/no_think` 可关）。
- 开思考后工具调用前输出 `reasoning_content`、多轮需回传（见 02-模型与工具调用 §3.4）。
- 来源：[qwen3.8-flash 模型信息](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)、[百炼深度思考用法](https://help.aliyun.com/zh/model-studio/deep-thinking)、[百炼视觉推理用法](https://www.alibabacloud.com/help/zh/model-studio/visual-reasoning)、[百炼图像与视频理解](https://help.aliyun.com/zh/model-studio/vision)。

### 2.5 GPT-5.6-Luna：`none` 档即非思考模式，官方「最低成本与延迟」档

- 官方模型页：`reasoning.effort` 支持 **`none`/`low`/`medium`(默认)/`high`/`xhigh`/`max`**；Reasoning 指南将其列为「lowest cost and latency」推荐档，Terra 次之。
- `none` = 非推理模式运行（Artificial Analysis 已按「Luna non-reasoning」单列供应商基准——佐证该模式真实可用）。
- 社区问题两类：部分第三方客户端/兼容网关不透传 `reasoning_effort`（Cline issue、Cursor 论坛）——自研直连不受影响，但走聚合网关时需留意。
- 来源：[GPT-5.6 Luna 模型页](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、[OpenAI Reasoning 指南](https://developers.openai.com/api/docs/guides/reasoning)、[Artificial Analysis（社区基准）](https://artificialanalysis.ai/models/gpt-5-6-luna-non-reasoning/providers)、[Cline #12798（社区）](https://github.com/cline/cline/issues/12798)、[Cursor 论坛（社区）](https://forum.cursor.com/t/byok-does-not-send-the-reasoning-effort-parameter-for-gpt-5-6-models/165529)。

### 2.6 Kimi K3 / MiniMax M3 / Gemini 3 Flash（对照）

- **Kimi K3**：K2.6 起 Thinking **始终开启**（无 disabled）；思考模式 temperature 固定 1.0，官方建议调用时**不要显式传 temperature**。对「响应速度优先」场景不利（除非平台另出快档）。来源：[Kimi 模型参数参考](https://platform.kimi.com/docs/api/models-overview)、[Kimi 思考模型文档](https://platform.kimi.com/docs/guide/use-thinking-models)。
- **MiniMax M3**：`thinking.type: "adaptive"(默认)/"disabled"`，**M3 可关**（M2.x 不可关）；M3 原生交错思考（Interleaved Thinking，每轮工具调用前思考）；另有 M2.5-Highspeed 高速档。来源：[腾讯云 TokenHub MiniMax 指南](https://cloud.tencent.com/document/product/1823/132246)、[MiniMax M3 工具与交错思维链文档](https://platform.minimax.cn/docs/guides/text-m3-function-call)。
- **Gemini 3 Flash**：`thinking_level`（离散档 low/medium/high）替代 2.5 的 token 级 `thinking_budget`；默认 dynamic（动态思考）；**未检索到 3 系完全关闭思考的官方档位**（2.5 可 budget=0；社区称 Flash 有 minimal≈512 token 档，需复核）。来源：[Gemini thinking 官方文档](https://ai.google.dev/gemini-api/docs/thinking)、[Gemini 3 开发者指南](https://ai.google.dev/gemini-api/docs/gemini-3)。

## 3. 思考模式的通用约束（跨厂商汇总，直接影响工程接入）

1. **思考模式下采样参数普遍失效**：DeepSeek 官方明确 `temperature/top_p/penalty` 设置不报错但不生效；Kimi K2.6+ 直接固定 1.0。即「思考模型 + 采样调参」大多不可组合。
2. **`reasoning_content` 的回传与输出**：Qwen 多轮工具调用需回传；GLM 自适应思考不保证每次返回；流式下思考内容以独立 delta 输出（vLLM/LMDeploy 服务端自动分离）——详见 02-模型与工具调用 §3.4。
3. **「自动升档」行为**：DeepSeek 社区口径中 Agent 类请求自动升到 effort=max；方舟 `thinking.type=auto` 亦为模型自判——**默认值不一定等于最快**。
4. **思考预算/强度 ≠ 关闭**：GLM-5.3-Flash（low 档）、Gemini 3（low 档）等只能「少思考」，首字延迟仍包含思考开销；只有 DeepSeek `disabled`/`none`、Qwen `enable_thinking=false`、Luna `none`、MiniMax `disabled`、方舟 `disabled` 是真·非思考路径。
5. **思考与工具调用的组合限制**：GLM 思考模式不支持强制工具调用（tool_choice 强制无效，见 02-模型与工具调用 §3.4）；DeepSeek 思考模式支持多轮「思考+工具调用」交替。

## 4. 与本项目现状的对应事实（仅列差距，不给方案）

1. 项目 `call_llm*` **不传任何思考相关参数**（`thinking`/`enable_thinking`/`reasoning_effort`/`thinking_budget` 均未出现）——接入上述任一模型时，行为 = 该厂商**出厂默认**：GLM-5.3-Flash 恒思考、DeepSeek 默认 enabled+high（社区口径）、Luna 默认 medium、豆包默认档未核实。对「响应速度优先」的聊天场景，默认档普遍不是最快档。
2. 项目未处理流式中的思考增量（`reasoning_content` delta）——问题清单 A7 已列；若模型思考且未设低档，思考内容全部发生在首字之前，直接拉长 TTFT。
3. 项目的 openai SDK 走 Chat Completions；DeepSeek/Gemini/Luna 的强度参数在 Chat/Responses 两侧参数名不同（`thinking.type` vs `reasoning.effort`），并非全厂商共用同一写法。
4. 项目 prompt 中的采样类约束（若有）在思考模式下可能静默失效（§3.1），当前代码未传 temperature，无实际冲突，但属接入时的认知前提。
5. doubao-seed-2.0-lite 若以「无思考 + 识图」形态使用，与项目现状（流式+tools+图）无协议冲突；其方舟接入亦为 OpenAI 兼容口径（方舟 docs 提供兼容端点）。
