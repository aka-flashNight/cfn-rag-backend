# 14 · 外部提示词预览接口

**文档角色**：对外接口说明（how to call）。本接口独立于终端聊天与对话插话两条主流程，只读汇编提示词，**不发起任何模型调用**。
**代码位置**：`api/prompt_preview_api.py`；注册于 `api/__init__.py`（`prefix="/game"`，上层 `prefix="/api"`）。
**引入版本**：后端 `3.0.1` 之后（提交 `255c9ff`），`3.0.2` 打包内置。

---

## 1. 一句话

给一个 NPC 名和一段字符串，拿回一份可以直接喂给大模型的 `messages`：里面是后端现成的 NPC 资料、角色扮演要求，以及六类混合检索结果；后端自己一个 token 都不花。

---

## 2. 基本信息

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| 路径 | `/api/game/prompt-preview` |
| 完整地址 | `http://127.0.0.1:7077/api/game/prompt-preview`（默认端口 7077） |
| 请求体 | JSON |
| 鉴权 | 无（仅监听 `127.0.0.1` 的本机单用户服务） |
| 是否需绑定存档 | 不需要 |
| 是否需 session | 不需要 |
| 模型调用 | **0 次**（返回体 `meta.llm_calls` 恒为 `0`，可用于自检） |
| 写盘 | 不写 session、不写长期记忆、不写覆盖层、不改 NPC 状态 |
| 交互式文档 | 服务运行时 `http://127.0.0.1:7077/docs` 可直接试调 |

---

## 3. 请求

### 3.1 字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `npc` | string | 否 | `""` | NPC 名称，要写**设定里的正式名**（如 `Andy Law`、`The Girl`）。为空或查不到时只返回通用资料，不报错 |
| `input` | string | 否 | `""` | 玩家说的话，或只用来做检索的关键词。允许为空 |
| `roleplay` | bool | 否 | `true` | `true`=附带角色扮演要求（说话方式 / 扮演约束 / 台词纪律）并输出「你现在扮演…」；`false`=只给资料，身份行改成中性「角色：…」 |
| 其他字段 | — | — | — | 模型配置为 `extra="ignore"`，多传的字段会被静默忽略（便于前端带上下文透传） |

### 3.2 示例

```bash
curl -s -X POST http://127.0.0.1:7077/api/game/prompt-preview \
  -H "Content-Type: application/json" \
  -d '{"npc":"Andy Law","input":"抗生素在哪能弄到？","roleplay":true}'
```

```python
import requests

resp = requests.post(
    "http://127.0.0.1:7077/api/game/prompt-preview",
    json={"npc": "Andy Law", "input": "抗生素在哪能弄到？", "roleplay": True},
    timeout=30,
)
data = resp.json()
messages = data["messages"]          # [{"role":"system",...},{"role":"user",...}]
```

```javascript
const r = await fetch("http://127.0.0.1:7077/api/game/prompt-preview", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ npc: "Andy Law", input: "抗生素在哪能弄到？", roleplay: true }),
});
const { messages } = await r.json();
```

## 4. 返回

### 4.1 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `npc` | string | 回显请求里的 `npc`（已 `strip`） |
| `npc_exists` | bool | 该 NPC 是否在 NPC 状态库里。`false` 表示只给了通用块，此时 `npc` 会被并进检索词 |
| `roleplay` | bool | 回显实际生效的开关 |
| `messages` | array | **固定两条**：`[{"role":"system","content":...},{"role":"user","content":...}]`，可直接整体发给模型 |
| `blocks` | object | 逐块清单，用于核对字数：`{"system":[{"name","chars"}...],"user":[...]}` |
| `retrieval` | object | 检索明细，见 4.2 |
| `meta` | object | `{"llm_calls":0,"read_only":true,"model_free":true}` |
| `elapsed_ms` | int | 服务端处理耗时（毫秒） |

### 4.2 `retrieval`

| 字段 | 类型 | 说明 |
|---|---|---|
| `chars` | int | 检索正文总字数（含实体提示，不含外层标题） |
| `sections` | array | 每个命中池一段：`{"header":"【你的过往台词示例】","count":16,"chars":788}`，`count` 为非空行数 |
| `empty_fallback` | bool | `true` 表示这次没拼进任何检索内容（检索引擎未就绪 / 索引重建中 / 全部未命中） |

## 5. 拼进去的块（与顺序）

### 5.1 system

| 顺序 | 块名 | 条件 | 内容 |
|---|---|---|---|
| 1 | 世界观背景概要 | 恒有 | 废土世界观概要 |
| 2 | 说话方式 | `roleplay=true` | 6 条口语化说话规则 |
| 3 | 角色扮演 / 角色资料 | NPC 存在 | `roleplay=true` 时为「你现在扮演游戏角色…」；`false` 时为中性「角色：（性别）（阵营）（身份或称呼）」 |
| 4 | 情绪标签 | NPC 存在 | 该 NPC 的可用情绪白名单 |
| 5 | 扮演约束 | `roleplay=true` 且 NPC 存在 | 「请始终以符合该角色身份、口吻、记忆和立场的语气，用简体中文说话。」 |
| 6 | 台词纪律 | `roleplay=true` 且 NPC 存在 | 「只输出角色台词，不写旁白、动作、心理或任何括号内容。」 |
| 7 | 脑补禁令 | 恒有 | 不得脑补未提供的设定 |
| 8 | 商店资料 | NPC 存在且有商店 | 仅「你经营商店，货品大致覆盖这些类型：[…]」，不含任务报酬描述 |
| 9 | 切磋 | NPC 存在 | 按「NPC 侧默认可用」给出可切磋提示 |
| 10 | 场景 | NPC 存在且能定位 | 所在场景与同场景 NPC |
| 11 | 形象 | NPC 存在且有形象描述 | 外貌资料 |
| 12 | 装备 | NPC 存在且有名目 | 该 NPC 身上的装备与简介 |
| 13 | 同阵营角色 | NPC 有阵营 | 同阵营其他 NPC 的简要设定；**已剔除 `$PC_CHAR` / `$PC_TITLE` 两个玩家占位符** |

空块不进 `blocks`，也不留空行（块之间用两个换行分隔）。

### 5.2 user

| 顺序 | 块名 | 条件 | 内容 |
|---|---|---|---|
| 1 | 检索到的设定资料 | 检索有命中 | 标题 + 六类检索池正文 + 实体提示（含物品获取途径） |
| 2 | 最新输入 | `input` 非空 | `【最新输入】\n{字符串}` |

两个块都为空时 `messages[1].content` 是空字符串，属正常返回。

## 6. 分支行为（实测）

| 场景 | 结果 |
|---|---|
| NPC 存在 + `roleplay=true` | system 最多 13 块（按商店/形象/装备/场景是否有数据取舍）；身份行为「你现在扮演…」 |
| NPC 存在 + `roleplay=false` | 去掉「说话方式」「扮演约束」「台词纪律」，身份行改中性 `角色：…`；其余资料块不变 |
| NPC 不存在 | `npc_exists=false`；system 只剩「世界观背景概要」「说话方式（若 roleplay）」「脑补禁令」；NPC 名并进检索词 |
| `npc` 为空 | 同「不存在」，检索词就是 `input` |
| `input` 为空 | 只返回检索块（命中时），无「最新输入」块 |
| 检索引擎未就绪 / 索引重建中 | 仍返回 200，`retrieval.empty_fallback=true`、`chars=0`，其余资料块照常 |
| 游戏数据不可用 | 仍返回 200；只少了场景、装备、商店、物品提示等依赖游戏数据的块（日志打 warning） |

## 7. 明确不含的内容

以下内容**不会**出现在返回里（与终端/插话主流程的差别，避免外部调用方误把它当完整生产提示词）：

1. 任何输出格式要求：JSONL、`add`/`closing`、字段名、字数上限、「立即输出」、说话人前缀。
2. 任务发布硬约束、委托草案流程、讨价还价、工具注册与工具说明。
3. 玩家侧全部信息：`$PC` 名字/身份/等级/进度/好感度、已播历史、剩余台词、物品账本。
4. 覆盖层改稿与记忆注入。

调用方若要约束输出格式，请在这两条 `messages` 之后自行追加自己的 system 指令；本接口不覆盖、也不校验你的格式要求。

## 8. 错误与限制

| 情况 | 表现 |
|---|---|
| 请求体不是合法 JSON / 字段类型不符 | `422`，FastAPI 标准校验错误（`{"detail":[...]}`） |
| 多传未知字段 | 忽略，正常 `200` |
| NPC 名不存在 | 不是错误，`200` + `npc_exists=false` |
| 检索引擎不可用 | 不是错误，`200` + `empty_fallback=true` |

限制与注意：

- **单用户本机服务**：没有鉴权，不要把这个端口暴露到公网。
- **性能**：常见几十毫秒到三百毫秒，取决于命中量与是否首次构建索引；索引重建期间会明显偏慢且 `empty_fallback=true`。
- **不做缓存**：每次请求都重新检索一遍；同一 `input` 反复调用结果稳定但耗时照付。
- **不落库**：接口返回内容不作为历史记录，调多少次都不会污染 session 或记忆。

---

## 9. 对原有流程的影响

- 只新增一个独立 `APIRouter`，在 `api/__init__.py` 加两行注册；不改 `game_api` / `dialogue_interject` 的任何函数、模型或路由。
- 路径 `/api/game/prompt-preview` 与现有 20 条路由无重叠（OpenAPI 全量枚举验证无重复路径）。
- 不注册工具、不改提示词常量、不改检索逻辑，因此终端聊天与插话的工具选择、提示词块、SSE 协议均不受影响。
