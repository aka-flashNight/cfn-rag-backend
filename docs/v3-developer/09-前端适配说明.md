# 09 · 前端适配说明（移交 cfn-terminal-web 项目）

> 本文档是后端 v3 重构对前端的**全部影响面**，供前端项目单独安排改造。
> 后端 SSE 契约以 `services/orchestrator/events.py` 为实现权威，本文为其说明文档。

---

## 1. SSE 事件契约（v3）

连接与端点不变：`POST /api/game/ask`（stream=true，`text/event-stream`；SSE 路径保持现网前缀 `/api/game/*`，见实施手记偏差 #2）。事件类型变更为：

| event | data（JSON） | 说明 |
|---|---|---|
| `meta` | `{emotion, favorability_change, favorability, relationship_level}` | **每回合有且仅有一次，且必先于一切 content**。收到即切立绘/更新好感条（对应旧 `mood_update`） |
| `content` | `{delta}` | NPC 台词增量。**只含台词**，不再有 `{花括号}` 系统消息、不会有工具调用残渣（旧的前端花括号解析逻辑可删除） |
| `tool_status` | `{tool, status, ui_hint}` | 后端工具进度。`status ∈ running/success/failed`；`ui_hint ≤12 字`（如「发布委托」「取消委托」） |
| `agent_status` | `{agent, phase, ui_hint}` | 后台工作进度：`agent ∈ task/search`；`phase ∈ drafting/repairing/searching/done/failed`；`ui_hint`（如「拟定委托中」「校验修正中」「查资料中」）。**现在需要真正展示**（旧代码注释说前端不显示，新版是等待体验的关键） |
| `system_notice` | `{text}` | 系统消息（草案已拟定/委托已发布/草案过期取消/错误说明）。替代旧 `{...}` 花括号约定，按系统样式渲染即可 |
| `done` | `{session_id, usage{prompt_tokens, completion_tokens, cached_tokens}}` | 回合结束。usage 可用来在设置页显示 token 消耗（可选展示） |
| `error` | `{code, message, retryable}` | 不可恢复错误。`retryable=false` 时提示用户检查配置 |

## 2. 典型时序（前端状态机参考）

### 2.1 纯聊天
```
meta → content×N → done
```

### 2.2 发任务（含后台拟定）
```
meta → content(过渡话)×2~5 → agent_status(task, drafting, 「拟定委托中」)
     → [可能出现 agent_status(task, repairing) 与一句过渡 content]
     → agent_status(task, done) → content(草案详述+询问接不接)×N
     → system_notice(任务草案已拟定，等待确认) → done
```
玩家回复「接」之后的确认回合：
```
meta → tool_status(confirm_agent_task, running) → tool_status(..., success)
     → content(确认话术)×N → system_notice(委托已发布) → done
```

### 2.3 讨价还价回合
```
meta → content(过渡)×2~3 → agent_status(task, drafting) → agent_status(task, done)
     → content(新方案+再次询问)×N → done
```

### 2.4 搜索回合
```
meta → content(过渡)×2~3 → agent_status(search, searching, 「查资料中」)
     → agent_status(search, done) → content(详答)×N → done
```

### 2.5 兜底与失败
- 任务拟定失败（极端）：`agent_status(task, failed)` → `content`(NPC 人设话术解释) → `done`，**不发** error 事件。
- 模型/网络不可用：`error{retryable}` → `done`。

## 3. 前端改造清单

1. **删除** `{花括号}` 系统消息解析逻辑 → 改渲染 `system_notice`。
2. `mood_update` → 改名 `meta`（字段语义不变）。
3. `content` 不再需要做工具残渣过滤。
4. **新增** `agent_status` 的展示组件：NPC 气泡区的「正在…」状态条（task=琥珀色/search=蓝色，附带 ui_hint）；done/failed 时消失。
5. `done` 事件的 data 形状**有变**：v2 携带完整 `NPCChatResponse`（reply/emotion/favorability/relationship_level/favorability_change），v3 仅 `{session_id, usage{...}}`。旧前端在 `onDone` 里用 `data.reply` 覆盖流式文本、用 `data.favorability` 等重绘状态，升级后会导致**回复气泡被清空**（实测症状见 §5.1），必须按 §5.1 迁移。
6. **移除**「立绘生成 / 解压立绘包」按钮与相关接口调用（后端已删该功能）。立绘改由游戏对话立绘 manifest 体系提供（协议见游戏项目 `docs/对话立绘查表映射-外部Python读取指南-2026-09-05.md`）：
   - 供图接口（v3 实际路径）：`GET /api/assets/illustration/{npc_name}/{emotion}` —— 后端按 manifest 查表 + `bounds` 裁剪，返回**已裁剪的人物本体 PNG**；请求的情绪缺失时后端走回退链兜底，查无角色/主角返回 404。
   - 头像接口不变：`GET /api/assets/avatar/{npc_name}`（原 `profiles/` 目录原文件直出，与立绘体系无关）。
   - 前端展示按 `meta.emotion` 拼上述接口即可，**无需自己实现查表或裁剪**；若需要整幅画布或游戏内取景效果，需在前端适配阶段另行与后端约定参数（当前接口不返回未裁剪原图）。
7. 设置页模型配置项不变（api_key/base/model/proxy 按会话传递），新增建议默认：`deepseek-v4-flash-vision-exp`。
8. 任务草案卡片的「接 / 不接 / 讨价还价」三个入口不变（本质都是发下一条消息）。

## 4. 兼容性

v3 后端与旧前端**不互相兼容**（事件语义已净化）。前后端需同步发版；版本号在 `done` 之前的 HTTP 响应头 `X-CFN-Version: 3.0.0` 提供，前端可据此提示用户升级。

## 5. 实测补充（2026-09-06，v3 后端实包与旧前端联调发现）

> 以下均为真实联调中复现的问题与对应的迁移要点，是对 §1/§3 的细化，供前端改造排期参考。

### 5.1 回复气泡「先显示后消失」——done 形状迁移（高优先）

**症状**：每发一条消息，content 流式正常打出，随后整条回复瞬间被清空（好感/情绪也可能异常）。

**根因**：旧前端 `Home.vue` 的 `onDone` 用 `data.reply` 覆盖流式累积文本、用 `data.favorability / data.relationship_level / data.emotion / data.favorability_change` 重绘状态（v2 的 done 即完整 `NPCChatResponse`，覆盖是防丢字的合理设计）。v3 的 `done` 只有 `{session_id, usage}`，`data.reply` 为 undefined → 气泡被空串覆盖。

**迁移要点**：
- 流式正文以 `onContent` 累积结果为准，`onDone` 只做收尾（清 tool_status 条、解除输入锁），**不要再用 `data.reply` 回写气泡**；
- 好感度 / 关系等级 / 情绪的终态改从 `meta` 事件读取（v3 的 meta 已带全量字段 `emotion / favorability / relationship_level / favorability_change`，见 §1；旧 `mood_update` 只带增量，这是语义增强）；
- 兼容期内可对 `data.reply` 做存在性判断兜底，但不要依赖它。

### 5.2 事件名与字段映射（旧 → 新速查）

| 旧前端监听 | v3 事件 | data 字段变化 | 影响 |
|---|---|---|---|
| `mood_update` | `meta` | 增补 `favorability`、`relationship_level` 全量终值 | 收不到 → 好感条/情绪不更新 |
| `system` | `system_notice` | `{text}` 不变 | 收不到 → 草案提示/委托结果等系统消息全部丢失 |
| `content` | `content` | 不变（纯台词） | 兼容 |
| `done` | `done` | **移除** `reply/favorability/...`，新增 `usage` | 回复气泡被清空（见 §5.1） |
| `error` | `error` | v2 `{error}` → v3 `{code, message, retryable}` | 旧前端读 `data.error` → 一律显示「未知错误」（实测复现），需改读 `message` |
| `tool_status` | `tool_status` | v2 `{text, tool_name}` → v3 `{tool, status, ui_hint}` | 旧前端读 `data.text` → 显示空文案，按 §3.4 重做时一并改 |
| （新增） | `agent_status` | `{agent, phase, ui_hint}` | 旧前端无此监听，等待期将没有「拟定中/查询中」反馈（§3.4） |

### 5.3 旧前端 localStorage 恢复配置会把 API Base 拼成畸形 URL

**症状**：重启页面（配置从 localStorage 恢复）后首条消息 404，后端日志可见请求 URL 被拼成
`https://api.deepseek.com/v1https://api.deepseek.com/chat/completions`。

**根因在前端**：恢复「player-settings」时把自动推导的官方 base（含 `/v1`）与用户自填 base 做了字符串拼接。修复方向：恢复配置时对 `api_base` 做一次合法性规整（去重 `/v1` 后缀、校验仅一个 scheme），或恢复后强制走一次与首次保存相同的规范化流程。属前端 bug，后端不做防御性兼容。
