## 1. 走查范围与分两段的原因

一段驱动脚本本想一次跑完「闲聊 → 草案 → 发布 → 任务完成事件 → 对话委派 → 事后闲聊」，
但它在**发布之后**用错了落盘根路径（写死成 BACK 项目根，真实 data_root 是游戏仓 `data/`），
于是读不到刚发布的任务、直接跳过任务完成与委派两段。日志逐字：

```
[4] 发布后落盘快照 → {"agent_tasks.json": null, "agent_text.json": null, "dialogue_overrides.json": null,
                      "task_text_overrides.json": null,
                      "_dir": "E:\\program\\cfn-rag-backend\\data\\rag\\agent_saves\\walk20261016", "_exists": false}
[5] 本槽已发布任务 id = None（rows=n/a）
!! 未找到已发布任务，跳过任务完成事件与委派验证
```

发布本身其实**已经成功落盘**（第二段读到 213507 即反证）。

处置：路径改成用后端自己的解析口径 `get_game_data_registry().data_root`，
**不重跑第一段**（省额度），新开第二段驱动接着验剩余功能。所以本记录分：

| 段     | 驱动脚本                                        | 覆盖                                                                                  | 真实 LLM 调用  |
| ------ | ----------------------------------------------- | ------------------------------------------------------------------------------------- | -------------- |
| 第一段 | `debug/full_flow_walk_20261016.py`            | bind/status 投影、纯闲聊＋检索、首次草案（路由＋任务子 Agent＋汇合）、确认发布与落盘  | 12 次          |
| 第二段 | `debug/full_flow_leg2_20261016.py`            | task-completed 契约（0 调用）、已完成委托拼接、主动委派对话修改（触发三）、改写后再聊 | 5 次           |

## 8. 缺陷与观察清单

### 缺陷（要改，按优先级）

- **D-1 检索轮 31.1 秒空窗**。`agent_status(searching)` 后到检索 done 之间没有任何玩家可见输出：
  `SearchRunner` 不推 `intermediate`，而过渡语桥的触发条件就是 `saw_intermediate`（`orchestrator/merge.py`）。
  对比：W2 任务子 Agent 推了 intermediate，首字压到 13.5 秒。
  **属产品决策**：要么让检索子 Agent 在检索完成时推一条 intermediate，要么允许 search 无 intermediate 也能说过渡语。
  本轮**没擅自改**——这是观感取舍，不是纯技术修复。
- **D-2 同行 meta 漏给玩家**（W3 现场）。已修（BACK `6dbffd1`：`split_meta_events` 在 JSON 完整且后面紧跟文字时按前缀切一刀，
  前缀同样要过 `_passes_meta_schema`；提示词明写「写完就换行、台词从第二行开始」；3 条锁测；全量 568 绿）。
  **但修复后的真机没再复现同行情形**，所以只能算单测层证据；下次走查若模型仍同行写法，要看日志里
  `meta 与台词同行（缺换行），已按 JSON 前缀切出` 这条 warning 有没有出现。
- **D-3 委派对玩家完全静默**。W5 后台跑了 16.4 秒、改了对话，SSE 侧没有任何事件；玩家不知道自己的一句话被采纳成永久改写。
  是否补一条 `system_notice`（例如「我把咱们这几句重新记了」）属观感设计，本轮未擅自加。

### 观察（现设计如此，等作者审美/口径裁定）

- **O-1 触发一依赖模型挂标记**。本轮草案没挂 `dialogue_rewrite`，于是任务完成只能走「不受理」。
  要不要按 `task_type` 由代码强制补挂（清理类完成必改对话），是收口期该定的口径问题。
- **O-2 Agent 新增对话组的 `Title`/`Char` 落成 NPC 名**：`[Andy Law / Andy Law / Andy Law]`，
  而任务侧对话是 `A兵团老大`／`Andy Law#微笑`。游戏内名牌会显示成「Andy Law / Andy Law」，观感待作者确认；
  改法是从 NPC 状态库取头衔、表情按 `reason` 选一个已有 char，属 `_line_defaults` 的扩展。
- **O-3 缓存命中稀疏**：6 轮只有 W2/W6 命中前缀缓存，延迟预算不能假设稳定命中。
- **O-4 后台任务子 Agent 用 4 轮上限**（`rounds=4`），本轮 R1 prepare＋R2 draft 就出草案，没测到轮次耗尽的兜底路径。
