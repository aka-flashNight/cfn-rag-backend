### 后期优化项（登记备查，未授权施工）

- **重要任务委派时把「发布前后几轮对话」整体拼进材料**（用户 2026-10-15 提出，明确**不是当前必须做的内容**）。
  现状＝触发一只给两样：`_load_publish_dialogue(publish_session_id)` 取**发布那场会话**的摘要＋摘要之后的
  原文（上限 `PUBLISH_DIALOGUE_LIMIT=40` 条），以及任务记录里的 `get_conversation` / `finish_conversation`
  台词原文（进 `task_block`）。缺的是「发布前几轮铺垫」与「完成后回到聊天的那几轮」——
  玩家回来交任务时说的话、NPC 当时的真实回应，子 Agent 现在看不到。
  **实现难度评估＝中等，但干净程度取决于一个前置**：
  1. *能干净做的部分*＝完成场次那几轮。`dialogue_jobs` 已有 `session_id` 列（触发二/三 有值，
     触发一恒空），只要受理当刻能拿到完成那一轮的聊天会话，按 `get_history(session_id, limit=N)`
     取尾 N 条即可，不需要新数据结构。难点只在**拿不到**：触发一走的是 HTTP 事件
     （`/api/integration/task-completed`），**当时没有会话上下文**，
     所以要么由游戏侧在事件里带 `session_id`（跨仓改动＋契约变更），要么在任务完成回写时
     （`turn.py` 的已完成委托检测那条路径）顺手记下当轮会话——后者是本仓内可做完的。
  2. *不干净的部分*＝发布场次。`publish_session_id` 已有，但「发布前几轮」需要先定位发布那一轮的
     **消息序号下界**再往前取窗口；现在只有 `get_summary_message_count_sync`（摘要边界）这一个切点，
     没有「第几条消息发布了哪个任务」的记录，得给消息表加任务 id 标注或按 `get_conversation`
     文本反查轮次边界——**反查不可靠**（同一段台词可复用、改写覆盖层后原文可能对不上）。
     真要干净做，需要新增「任务 → 发布消息序号」的一列（写侧在 `task_tools` 落盘时顺手记），
     属数据层扩展，且要考虑旧存档没有这一列时的缺位表现（不拼，而不是猜）。
  3. *成本与噪声*：多拼几轮会挤占子 Agent 首轮的材料预算，而改对话真正需要的往往只是
     「他当时怎么说的」这一句；建议做的时候按**只取尾 3~5 条**起步，并保留空块不出现的现口径。
  4. 触发二/三（关系变化、态度变化、关键信息）本身就是聊天轮，材料里已有当轮上下文，
     **不需要**这条优化。

## 2. 模式速查（实现时的判定口径）

| 判定 | 规则 |
|---|---|
| 运行模式 | 启动参数含 `--embedded` → embedded；否则 standalone。standalone 进程之后被游戏 bind：获得存档作用域，但不改变已开浏览器行为。 |
| 任务写盘落点 | bind 有效 → `data/rag/agent_saves/<slotKey>/`（文件级隔离，一存档一整套）；否则共享 `data/task/agent_tasks.json` + `data/task/text/agent_text.json`。 |
| 对话覆盖落点 | bind 有效 → 同目录下 `task_text_overrides.json`（任务文本 `$占位符` key 级）与 `dialogue_overrides.json`（NPC 日常对话组级）；standalone 不产覆盖层。 |
| 模型可改范围 | NPC 日常对话 + 当前存档**未完成**的既有任务对话；Agent 任务对话一律不改（仍进检索语料）。 |
| NPC 状态作用域 | bind 有效 → `saves.<slotKey>`；否则 `global`。 |
| 长期记忆默认 | embedded 开 / standalone 关；玩家设置持久化覆盖默认；standalone 作用域键 `__standalone__`。 |
| 投影刷新 | 打开面板/读档/存档落盘/任务完成时游戏推 bind（幂等，同槽位＝刷新）；exe 永不主动拉取；进度判断以事件当刻推送为准。 |
| 阶段推导 | bind 投影的 `task_chains_progress["主线"]` 链值按节点边界归 1–4（21/27/36/67）或 5 诺亚（68–779）；链值 ≥780（主线收束）按等级模拟：<40 诺亚 / 40–49 雪山 / ≥50 已通关；不可判＝null（消费方回落自填值）。 |
| 场景给 AI | 绑定且场景段可显示时注入会话态块（玩家名行后）：战斗中给关卡名（`inCombat` 门控 `stageName`）、非战斗给归一后 `label`；未绑定不注入。 |
| 对话联动委派 | 两类信号（任务完成事件 + 聊天关系/事实信号）→ 关键性初判 + 频率限制，合适才委派子 Agent；子 Agent 自主修/加/不动。 |
| 对话联动受理 | 仅 embedded 且事件 `slot_key`＝当前绑定槽位；其余记录后 dismissed。 |
