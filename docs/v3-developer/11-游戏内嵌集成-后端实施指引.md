## 2. 模式速查（实现时的判定口径）

| 判定 | 规则 |
|---|---|
| 运行模式 | 启动参数含 `--embedded` → embedded；否则 standalone。standalone 进程之后被游戏 bind：获得存档作用域，但不改变已开浏览器行为。 |
| 任务写盘落点 | bind 有效 → `data/rag/agent_saves/<slotKey>/`（文件级隔离，一存档一整套）；否则共享 `data/task/agent_tasks.json` + `data/task/text/agent_text.json`。 |
| 对话覆盖落点 | bind 有效 → 同目录下 `task_text_overrides.json`（任务文本 `$占位符` key 级）与 `dialogue_overrides.json`（NPC 日常对话组级）；standalone 不产覆盖层。 |
| 模型可改范围 | NPC 日常对话 + 当前存档**未完成**的既有任务对话；Agent 任务对话一律不改（仍进检索语料）。 |
| NPC 状态作用域 | bind 有效 → `saves.<slotKey>`；否则 `global`。 |
| 长期记忆默认 | embedded 开 / standalone 关；玩家设置持久化覆盖默认；standalone 作用域键 `__standalone__`。 |
| 投影刷新 | 打开面板/读档/存档落盘/任务完成时游戏推 bind（幂等，同槽位＝刷新）；exe 永不主动拉取；进度判断以事件当刻推送为准。 |
| 阶段推导 | bind 投影的 `task_chains_progress["主线"]` 链值按节点边界归 1–4（21/27/36/67）或 5 诺亚（68–779）；链值 ≥780（主线收束）按等级模拟：<40 诺亚 / 40–49 雪山 / ≥50 已通关；不可判＝null（消费方回落自填值）。 |
| 场景给 AI | 绑定且场景段可显示时注入会话态块（玩家名行后）：战斗中给关卡名（`inCombat` 门控 `stageName`）、非战斗给归一后 `label`；未绑定不注入。 |
| 对话联动委派 | 两类信号（任务完成事件 + 聊天关系/事实信号）→ 关键性初判 + 频率限制，合适才委派子 Agent；子 Agent 自主修/加/不动。 |
| 对话联动受理 | 仅 embedded 且事件 `slot_key`＝当前绑定槽位；其余记录后 dismissed。 |

## 3. 不做清单（防止范围蔓延）

- 不启用 `mcp_server/`（现状保留未启用）；不新增 socket/命名管道 IPC（exe→游戏方向只用既有文件轮询）。
- 不读/写游戏存档文件（SOL、launcher `saves/*.json` shadow）；进度信息一律来自游戏 bind 投影。
- 不改写游戏 base 对话 XML；不重构任务协商管线与 RAG 检索内部。
- 不在正式数据目录（`data/task/`、`data/dialogues/` 等）里写按存档生成物：一切按存档产物只进 `data/rag/agent_saves/<slotKey>/`，避免与正式数据混放。
- 7080 段端口动态分配逻辑保留（standalone 用），embedded 不起该服务。
