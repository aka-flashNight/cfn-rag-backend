## 打包 CFN-RAG v3 exe（已产出）

完整流程（本次实测通过）：

1. 构建前端：`cd E:/program/cfn-terminal-web && npm run build`（vue-tsc + vite，约 5s）
2. 同步产物：`rm -rf E:/program/cfn-rag-backend/dist && cp -r ../cfn-terminal-web/dist ./dist`
   - 后端 dist/ 就是前端构建产物，无自动同步脚本，必须手动拷
3. 打包：`.\venv\Scripts\Activate.ps1` 后 `python scripts/build_exe.py`（约 2m50s）
   - 输出到项目根 `CFN-RAG.exe`，固定名，会删除并覆盖旧版
   - 本次产物 91.2 MB（预算 ≤160MB，超了脚本 exit 2）
4. 启动：exe 必须与 `resources/`（游戏资源，现位于 E:/program/resources）同级；
   也可用 `CFN_RESOURCES_DIR` / `CFN_GAME_PROJECT_DIR` 指定。

### 实测结论 / 坑
- 打包前必须关闭所有 CFN-RAG.exe 进程，否则删旧 exe 报 PermissionError 直接退出。
- onefile 首次启动约 90s 才监听 7077（91MB 自解压为主）；后端启动任务本身只要 0.62s
  （向量索引命中时）。日志 `E:/program/cfn-rag.log` 里 startup 段可佐证。
- 索引未命中时后台重建约 20s（4180 条），期间检索降级 BM25-only。
- 冒烟验证：`curl 127.0.0.1:7077/api/health`、`curl 127.0.0.1:7080/api/health`（前端反代）均返回 ok。
- exe 有全局单实例互斥体，重复启动会弹窗提示；7077+7080 同时被占也会早退。
- `launcher.py` 注释里提到的 `--rebuild-vector` 参数在 `build_exe.py` 的 argparse 中并不存在（注释过时）。

## 排查「玩家接了任务但没发布」+ 修复

- 现象：玩家说「我接了」后 NPC 反复追问确认，3 轮后出现「过期的委托草案已取消」，任务没发布。
- 根因：草案确认靠模型 meta 行 `{"act":{"kind":"task_confirm"}}` 触发（turn.py 同步路径）。那 3 轮模型 act 全为 null/解析失败 → 按纯聊天处理，`draft_keep_turns=3` 计数到顶触发自动过期。若 confirm 真发过但失败，前端会看到「委托确认失败：…」，而玩家没看到 → 证明模型根本没发。
- 诱因：meta 协议唯一示例是 `"act":null` 有锚定效应 + 防御性提醒过多；act 写成字符串（`"act":"task_confirm"`）会被 parse_meta_obj 静默丢弃且无日志。
- 修复（2026-09-06）：
  1. `services/llm/meta.py`：act 字符串形态宽容纠正（task_confirm/cancel/draft）；非法 act、首行 JSON 解析失败、漏发 meta 行均加日志。
  2. `meta_prompt_block` 有草案分支：补 task_confirm 完整示例行 + 明确接受话术清单（「我接了」等）+ 硬性要求「调整后玩家再次接受必须本轮 task_confirm，同一草案最多追问确认一次」；「我接但要多点奖励」仍按 task_update 走，认可后再 confirm。
  3. `turn.py`：有草案但 act=null 时打 warning（含玩家消息），便于日志定位。
  4. 新增测试 `test_act_as_string_coerced` / `test_act_string_with_required_payload_becomes_null`，全套 172 passed。
- 未做（待决策）：act=null + 玩家消息强接受词时的关键词兜底 confirm（有误判风险，先靠 prompt 修复观察）。
